# Разработка SMC Visualizer Pro

Спецификация — `docs/`, руководство пользователя — [`docs/USER_GUIDE.md`](docs/USER_GUIDE.md). Этот файл — как устроен код и как с ним работать.

## Сборка

```bash
python3 build/build.py                  # обе цели: dist/SMC_Visualizer_Pro.pine и dist/SMC_Pro_Setups.pine + lint
python3 build/build.py --target setups  # одна цель (core | setups)
python3 build/build.py --check          # + проверка синтаксиса (нужен pip-пакет pynescript), ~3–4 мин на цель
```

- Pine не поддерживает `include`, а invite-only публикация — один файл. Поэтому исходники модульные, а публикуется собранный монолит (ADR-04).
- **С v0.4.1 публикуются два индикатора из одних исходников (ADR-13):** `core` — SMC Visualizer Pro (разметка, история, панели, алерты структуры), `setups` — SMC Pro · Setups (сетапы, их панель и алерты). Один монолит v0.4.0 перестал компилироваться в TradingView (таймаут).
- Код одной цели огорожен в модуле:

  ```pine
  //#if setups
  ...           // только в SMC Pro · Setups
  //#else
  ...           // только в SMC Visualizer Pro
  //#endif
  ```

  Флаги цели — в `build/targets.json`. Блоки не вкладываются; директивы можно делать с отступом (внутри функций), они удаляются при сборке.
- **Бюджет компиляции:** ≤ 30 тыс. **токенов кода** и ≤ 4000 строк на цель — сборка печатает `WARNING`, если больше. Токены кода: без комментариев, строковый литерал любой длины — один токен (с v0.8.1; раньше считались слова внутри строк, ≈12% счёта, и бюджет был 34 тыс.). Замер: v0.3.0 — 26,7 тыс. токенов кода, компилируется около минуты; v0.4.0 — 35,1 тыс., «Pine compilation was timed out» (2 мин); время растёт быстрее размера. Тексты подсказок и панелей на бюджет почти не влияют.
- **`dist/` не редактируется руками.** Правки — только в `src/`, затем пересборка.
- Версия — в файле `VERSION`, подставляется в заголовок и константу `BUILD`.
- `--check` использует pynescript (ANTLR-парсер Pine). Он ловит синтаксис, но не типы и не ошибки времени выполнения: окончательная проверка — компилятор TradingView. На большом файле проверка идёт 2–3 минуты. Если pynescript установлен в другом окружении, укажите `PINE_PARSER_PYTHON=/path/to/python`.

### Правила lint (ошибка сборки)

| Правило | Почему |
|---|---|
| Нет `varip` | Детерминизм history = realtime (ADR-10) |
| Нет `timenow` | То же (§20.8) |
| Нет `chart.left_visible_bar_time` / `chart.right_visible_bar_time` | Иначе TradingView пересчитывает весь скрипт при каждой прокрутке и зуме — лаги (v0.6, ADR-14) |
| `lookahead_on` только со смещением `[1]` | Иначе repaint (§4.7) |
| Отступы кратны 4, без табов, без переносов строк | Переносы в Pine требуют особых отступов; проект их не использует |
| Нет восходящего цикла до `size() - 1` без проверки | В Pine `for i = 0 to -1` выполняется дважды (0, −1) |
| Блоки `//#if` закрыты и не вложены | Иначе цель соберётся не из того кода |
| Строковый литерал закрыт на своей строке | Строка не может переходить на следующую; перенос внутри текста — только `\n` |
| Ключевые слова Pine (`to`, `by`, `in`, …) не используются как имена параметров и переменных | Компилятор отвергает такое объявление |
| Имена встроенных типов и пространств (`text`, `line`, `label`, `box`, `table`, `color`, `array`, …) не используются как имена переменных, полей и членов enum | CE10150 «cannot be used as a variable or function name» (v0.5.0: член enum `text`) |
| Входы одной строки настроек (`inline`) и одной группы (`group`) объявляются подряд | Иначе строка или группа в диалоге настроек разрывается (v0.8.1: положение панели Setup под алертами) |
| У каждой строки настроек есть подсказка (`tooltip` у одного из входов строки) | AC-38: 100% настроек с подсказкой |

## Карта модулей

Порядок важен: в Pine функция и глобальная переменная должны быть объявлены до использования.

Колонка «Цель»: в какой индикатор попадает модуль (`оба` — общий код, местами с блоками `//#if`).

|---|---|---|---|
| `00_header` | — | оба | `//@version=6`, объявление `indicator()` |
| `01_constants` | X | оба | Коды событий, видов и состояний, фиксированные параметры A.19 |

| `03_inputs` | X | оба (визуальные — core, группа 9 — setups) | Панель настроек (§14.4), эффективная конфигурация, потолки режимов (ADR-09) |

## Ожидаемые предупреждения TradingView

| Код | Где | Почему так и не меняем |
|---|---|---|
| CW10003 «function should be called on each calculation» | — | С v0.5.1 не возникает: функции, читающие историю баров, вызываются на каждом расчёте с флагом `cf` (подтверждённый бар) и работают только при нём. Новую такую функцию вызывайте так же — не из `if` / `for` |
| CW10013 «Shadowing variable» | — | Не допускается: проверяет `build.py` (локальная переменная с именем глобальной). Поля UDT и члены enum тенью не считаются |

## Инварианты, которые нельзя нарушать

1. Логика меняет состояние только внутри `if barstate.isconfirmed` в `90_main`.
2. Модули `6x` и `95` только читают состояние. Relevance Score не используется логикой (ADR-11).
3. Все `ta.*`, `request.*`, пивоты — на глобальном уровне в `10_data`, на каждом баре. Функции движков читают их через `[]`.
4. Любое динамическое смещение `[]` меньше `MAXBACK_GUARD` (550). Буферы задаются через `max_bars_back` в `10_data`.
5. Новый порог задаётся в ATR или тиках, не в процентах цены.
6. Новое событие добавляется в `01_constants`, в `f_evName` и в каталог `docs/03-domain-models.md` §6.4.
7. Визуал берёт цвета и прозрачности только из `60_visual_tokens`.
8. HTF: каждое значение детекции из `f_htfState` возвращается со смещением `[1]` при `lookahead_on`; без смещения — только время открытия и номер текущего HTF-бара. Новые HTF-объекты определяются трекерами `hLast*`, которые не обновляются на баре графика, пересекающем границу HTF-бара (`htfHold`).
9. Рендер: лимиты окна делятся между сегментами с округлением вниз (`f_quota`), отбор внутри сегмента — через `f_spreadPick`; сумма долей не должна превышать пул. Объект попадает в архив, только если настройки отображения могут его показать (`f_zoneShown`, `f_liqArchive`).
10. Сетапы меняют состояние только в `f_setupStep` (подтверждённый бар, после Context, не в warm-up); композиция `63` только читает их.
11. **Движки и настройки, влияющие на расчёт, — общие для обоих индикаторов** и никогда не огораживаются `//#if` (ADR-13): иначе сетапы строились бы по другой разметке, чем нарисована. Новый вход движка добавляется в подпись `f_cfgSig` (`03_inputs`). Визуальный вход, который читает общий код, в цели `setups` заменяется константой в ветке `//#else`.
12. Каждая цель — в бюджете компиляции (≤ 30 тыс. токенов кода). Новые функции по умолчанию идут в `setups`; при приближении к бюджету — выносить, а не дописывать.
13. **Отрисовка — только на последнем историческом баре и один раз на закрытии каждого realtime-бара** (`barstate.islastconfirmedhistory or (barstate.isrealtime and barstate.isconfirmed)`): между закрытиями логика не меняется, перерисовывать нечего. История рисуется по окну последних `histDepth` баров, а не по видимой области (ADR-14). Всё, что зависит от масштаба (ширина подписей, мелкие зоны, шаг тегов), оценивается для `VIEW_BARS` баров на экране, а не по ширине окна.
14. Новый инвариант движка — проверка в `f_engineChecks` (`26_checks`), сетапа — в `f_setupChecks` (`30_setup`). Проверки выполняются только в Debug и ничего не меняют.
