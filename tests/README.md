# Проверка сборки в TradingView

## v0.5.0 — алерты и webhook

**Как создать алерт:** на графике с SMC Pro · Setups → Alert → Condition: «SMC Pro · Setups» → **Any alert() function call** → Webhook URL (для шлюза) → Create. После изменения настроек индикатора алерт нужно пересоздать.

| # | Проверка | Ожидание |
|---|---|---|
| 1 | Alert message = Text, Events = Setups | На READY / TRIGGERED / TP / SL / INVALID сетапа грейда ≥ «Alert min grade» приходит одна строка на бар: `SMC Pro · ETHUSDT 240 · LONG READY · Sweep Reversal · A 7.1 · E … · SL … · TP1 … · RR … · Sweep → CHoCH → …` |
| 2 | Alert message = JSON | Сообщение — валидный JSON (проверьте любым JSON-валидатором): `schema`, `msg_id`, `cfg`, `events[]`, у сетапа — `setup` и `plan` |
| 3 | Без ожидания realtime | Display Mode = Debug, Advanced → «log events» → Pine Logs: строки JSON для баров с событиями |
| 4 | Events = Setups + key events | Добавляются swing BOS / CHoCH, свипы major-ликвидности, смена HTF bias |
| 5 | Snapshot every N bars = 5 | При READY / ACTIVE сетапе без событий — сообщение со `snapshot` раз в 5 баров |
| 6 | Статические алерты | «Setup READY / TRIGGERED / INVALID» работают как раньше |

## v0.4.1 — два индикатора: что проверить

С v0.4.1 вместо одного скрипта — два (ADR-13). Каждый добавляется в Pine Editor как отдельный новый индикатор.

| # | Проверка | Ожидание |
|---|---|---|
| 1 | Компиляция `dist/SMC_Visualizer_Pro.pine` | Без ошибок и без таймаута; в первых строках `build 0.4.1`. Засеките время компиляции |
| 2 | Компиляция `dist/SMC_Pro_Setups.pine` | Без ошибок и без таймаута; в первых строках `SMC Pro · Setups · build 0.4.1` |
| 3 | SMC Visualizer Pro на графике | Как v0.3: зоны, уровни, структура, история, сессии; Ribbon без сегмента SETUP; Dashboard без строк SETUP / QUALITY |
| 4 | SMC Pro · Setups на графике | Композиции сетапов (зона входа, Entry / SL / TP, карточка); панель Setup справа внизу: SETUP, QUALITY, PLAN, INVALID, CFG. Зон, уровней и истории разметки этот индикатор не рисует |
| 5 | Совпадение настроек | Dashboard SMC Visualizer Pro → Dashboard size = Expanded → строка MODE: `cfg NNNN`. То же число — в строке CFG панели Setup. Измените, например, Structure preset только в одном индикаторе — числа разойдутся |
| 6 | Сетапы опираются на разметку | Свип и CHoCH/BOS в цепочке карточки видны на SMC Visualizer Pro в тех же местах (при одинаковом cfg) |
| 7 | Алерты | Структурные алерты — в SMC Visualizer Pro; «Setup READY / TRIGGERED / INVALID» и «Any alert() function call» — в SMC Pro · Setups |
| 8 | Скорость | Время загрузки обоих и пересчёт при прокрутке; если есть возможность — Pine Profiler по каждому |

## v0.4.0 — сетапы: что проверить

Сборка: в первых строках файла `build 0.4.0`; в Ribbon появился сегмент `SETUP —` / `LONG READY A`.

| # | Проверка | Ожидание |
|---|---|---|
| 1 | Компиляция | Без ошибок. Пришлите текст ошибки и номер строки, если будет |
| 2 | ETHUSDT 15m, Normal, листайте историю | Появляются композиции сетапов: зона входа, Entry (толстая синяя), SL (красная), TP1–TP3 (зелёный пунктир) с ценой и R, карточка `LONG · A 7.1   E …` с цепочкой и `RR 1:… · SL … ATR` |
| 3 | Тултип карточки | Разбор баллов по факторам (HTF, Discount/OTE, свип, сдвиг, POI, killzone, RR, штрафы), план и пометка ANALYTICAL |
| 4 | Стадии | FORMING — пунктирный контур без SL/TP; READY — полная композиция; после входа — маркер ● и `TP1 ✓`; завершённые затухают с итогом `✓ +…R` / `✕ SL −1R` / `✕ INVALID · …` / `⌛ EXPIRED · …` |
| 5 | Логика Sweep Reversal | Перед сетапом есть снятие ликвидности (`SSL ✕`), затем CHoCH/BOS вверх от свипа, зона входа — FVG/OB этой ноги в нижней половине диапазона |
| 6 | SL и TP | Long: SL ниже минимума свипа на буфер; TP1 — ближайшая BSL не ближе 1R; RR до последней цели ≥ Min RR (2.0) |
| 7 | Dashboard | Строки SETUP и QUALITY (`7.1 / 10 · A ▮▮▮▮▮▮▮▯▯▯`); в Expanded — PLAN и INVALID; без сетапа — `— watching BSL …` |
| 8 | Режимы | Clean: только линии (без боксов прибыли/риска), грейд A и выше. Normal: до 6 прошлых сетапов в видимой части графика (v0.4.2), Analysis: до 10 |
| 9 | Пресеты | Conservative — меньше сетапов (READY от A, без сетапов против HTF); Aggressive — больше (READY от C) |
| 10 | Алерты | «Setup READY / TRIGGERED / INVALID»; для подробного текста — алерт «Any alert() function call» |
| 11 | Warm-up | На первых барах истории (warm-up) сетапов нет |

## v0.3.0 — что проверить

Сначала убедитесь, что загружена новая сборка: в первых строках файла `build 0.3.0`; в Ribbon первым сегментом идёт `HTF 4H ▲ BULL` (или другой ТФ). Если подписи зон выглядят как `FVG×3+BB+IFVG` — это старая сборка v0.1.

| # | Проверка | Ожидание |
|---|---|---|
| 1 | Обычный масштаб (150–300 баров, ETHUSDT 15m) | Левая половина экрана тоже размечена: завершённые зоны (светлая заливка, пунктирная рамка), пробои, снятая ликвидность, сессии |
| 2 | Отдалите график на 1000–3000 баров | Разметка распределена по всей ширине без пустых полос; в Debug-таблице `VIEW … · N seg`, пулы `BOXES/LINES/LABELS` не переполнены |
| 3 | Прокрутите далеко влево (несколько тысяч баров) | История есть и там; в Debug подсказка строки ZONES показывает, с какого бара хранится архив |
| 4 | Подписи активных зон | В колонке тегов справа от последней свечи (вместе с BSL/SSL, EQ, OTE, `◀ 63%`), не внутри боксов и не на свечах; близкие теги сливаются, при отдалении тоже |
| 5 | Подписи BOS / CHoCH | Не заходят на свечи пробоя; при отдалении сокращаются до `BOS↑` или стрелки, на совсем узких пробоях остаётся линия. У пробоев у левого края подпись прижата к краю экрана |
| 6 | Сессии на тёмно-синем фоне | Боксы Asia / London / NY хорошо видны: светлые оттенки, рамка, название над максимумом. При сильном отдалении названия у узких сессий скрываются — сессию определяет цвет. Прозрачность — «Session fill transparency» |
| 7 | Ribbon и Dashboard | Текст крупнее (настройка «Panel text size»), первый сегмент Ribbon — HTF; в Dashboard строка HTF |
| 8 | HTF-объекты | Линии `◆4H BOS↑` / `◆4H CHoCH↓` толщиной 2; зоны `◆4H OB` с рамкой; уровни `◆4H BSL` |
| 9 | HTF без перерисовки | Bar Replay через закрытие 4H-бара: HTF-объекты появляются на первом баре после закрытия HTF-бара и потом не меняются. То же на недельном графике через границу месяца (HTF = M) |

| 11 | Ручной HTF ниже ТФ графика (например, 15 на H1) | Ribbon: `⚠ HTF ≤ TF`, HTF-объектов нет |
| 12 | Молодой инструмент (мало истории на HTF) | Ribbon: `HTF 4H ⚠`, MARKET считается по структуре графика |

# Проверка сборки в TradingView · v0.1.0

Сборка проверена только офлайн (синтаксис + lint). Это первая проверка компилятором TradingView, поэтому порядок такой: компиляция → смоук-тест → функциональные проверки.

## Шаг 1. Компиляция

1. Откройте Pine Editor → New → Indicator, удалите шаблон.
2. Вставьте всё содержимое `dist/SMC_Visualizer_Pro.pine` → **Add to chart**.
3. Если есть ошибка, пришлите текст ошибки и номер строки. Номер относится к файлу `dist/`, по нему находится модуль в `src/`.
4. Отдельно пришлите **предупреждения** (жёлтые), если они есть.

## Шаг 2. Смоук-тест (5 минут)

Инструмент: EURUSD или BTCUSD, ТФ M15, режим **Normal**.

| # | Проверка | Ожидание |
|---|---|---|
| 1 | Индикатор загрузился без runtime-ошибки | Нет красного значка ошибки у названия |
| 2 | Status line | Только «SMC Pro», без списка значений настроек |
| 3 | Ribbon внизу по центру | `STR ▲ BULL` / `STR ▼ BEAR`, сессия, `DISC/PREM %`, LIQ |
| 4 | Dashboard справа вверху | MARKET, STRUCTURE, SESSION, LOCATION, LIQUIDITY, TARGET ↑/↓ |
| 5 | Структура | Последние 3 swing BOS/CHoCH пунктиром с подписями |
| 6 | Ликвидность | Золотистые линии BSL/SSL с тегами справа; ◆PDH/◆PDL |
| 7 | Зоны | Не больше 2 OB и 2 FVG выше и ниже цены; FVG без рамки, OB с рамкой |
| 8 | Диапазон | Пунктир EQ, полупрозрачная полоса OTE, шкала-гейдж справа от цены |
| 9 | Режим **Clean** | Заметно меньше объектов, Dashboard скрыт, Ribbon остаётся |
| 10 | Режим **Analysis** | Появляются iBOS/iCHoCH, HH/HL, больше зон и история свипов |
| 11 | Режим **Debug** | Таблица слева: бюджеты, реестры, объём; на объектах #ID и R |
| 12 | Светлая тема | Цвета перестраиваются, текст читается |

## Шаг 3. Функциональные проверки

| Область | Что проверить | Критерий (docs §27) |
|---|---|---|
| No-repaint | Bar Replay 100+ баров: метки BOS/CHoCH, свипы и зоны не исчезают и не меняются после закрытия бара | AC-06 |
| Свип vs пробой | Тень за уровнем с закрытием обратно → `SSL ✕`/`BSL ✕`; закрытие за уровнем без возврата 2 бара → линия обрывается без ✕ | AC-14 |
| OB | Бокс стоит на последней противоположной свече перед импульсом к пробою | AC-17 |
| FVG | Бокс только при реальном разрыве; на открытии сессии акций (AAPL M15) гэп не размечается | AC-18 |
| Конверсия | Закрытие телом за дальней границей OB → BB или MB с пунктирной/точечной рамкой | AC-20 |
| Сессии | NY time: London KZ 02:00–05:00, NY AM KZ 07:00–10:00 в любое время года | AC-23 |
| PDH/PDL | Совпадают с high/low предыдущего дневного бара | AC-16 |
| Алерты | Создать алерт «BOS ↑ (swing)» — срабатывает только на закрытии бара | AC-07 |
| Производительность | Pine Profiler: время расчёта на M15 / 5000 баров | AC-03 |
| Debug-журнал | Advanced → «log events», Pine Logs: строки `EV|…` | §19.1 |
